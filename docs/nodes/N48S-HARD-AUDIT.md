## 本轮新增代码与反例

`tools/delivery/review_n48s_outcome.py` 不导入原打包器、产品或测试辅助函数，
不执行 EXE、SQL 或网络。`test_review_n48s_outcome.py` 测试该复核器，修改仅在内存覆盖层，
不改写原始证据。每种 Python 模式：8 个测试方法通过，36 个具体证据篡改反例均拒绝。
包括伪造稳定版/真实消费标记、布尔计数、缺阶段/错顺序、替换测试程序或测试入口、
用回读替代运行、改错 Python 模式、伪造费用后重算摘要、所有阶段快照协同篡改、
旧包身份/安装脚本变化、缺失/重排 55 步，以及原始输出字节改变。

本轮审核器初始实现确有一处覆盖缺口：只比较多个快照相等，未将每份快照绑定到原始
CLI 输出。合成探针同时修改一个宿主六份快照中的事实原文，初始复核器仍接受。
修正后从 120 条原始 CLI stdout 重建这 24 份快照，同一探针被拒绝，并加入回归测试。
这属于本轮新审核代码的缺陷，不是产品事实或回执丢失，也不是原生测试失败。
初始代码、接受反例结果及修正后测试均保留在证据交付中。

另外两次初始复核失败分别因入口文档按 LF 而非实际 Windows CRLF 比较，以及把原
PowerShell 空错误字符串误认为 null。均改为匹配固定源码约定的精确表示，不放宽正文、
类型或断言。原日志保留。更早 PR 候选中修正的元数据类型和 PE 区间问题为继承实现，
本轮未取得其所有失败原件，不冒称本轮新修产品。
