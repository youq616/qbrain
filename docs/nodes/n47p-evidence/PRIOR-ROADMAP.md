# Qbrain 完成路线与回合估计

更新：2026-09-19。基于主路线 Issue #2、N47M/N47N 已接受范围和 N47O 交付工作。
这是工程规划估计，不是承诺、后台排程或已经执行的结果；每轮结束重新校正。
“回合”指一次实质开发、测试、自审与入库，不把一次工具调用算作一个回合。

## 当前定位

核心实现及多轮正确性/安全边界修复已经完成；正在从已审核开发预览转入日常使用
验收和产品收口。不是从零开发，也不是所有剩余工作都只是打包。
保留 Windows 原生 C++20、PowerShell、默认 SQLite；不引入必需 Docker/WSL 服务。

## 两个不同的完成标准

### 日常可用 v1 验收目标：本次交付后预计还需 4–6 个实质回合

这是优先交付里程碑，不把广义优化路线中尚未实现的能力改写成“已完成”。
限定为 Windows 11、SQLite、既有 Claude/Codex 接口、明确授权的采集/整理/召回、
原话来源/撤回机制、升级卸载和可诊断失败。使用可复现样本和实际宿主证据证明
已保存的记忆能在后续会话被使用，关键故障不损坏数据、不绕过采集同意。

| 剩余工作流 | 预计回合 | 必须产出的验收证据 |
| --- | ---: | --- |
| 安装升级/故障恢复与其他高风险入口收口 | 1–2 | 原目录/配置保留、故障恢复、错误参数不误写、完整回归；不重复已证明的安装夹具 |
| 真实客户端生命周期与实际召回消费 | 1–2 | 补尚未证明的宿主/场景，保留已验收结果；登录、客户端信任等确需本机时只给一个完整提示词 |
| 有代表性任务、性能/成本与 v1 最终验收 | 2 | 同资料同模型可复现比较、明确费用/正确率边界、升级说明、候选发布、自审及用户可用性检查 |

上述工作按合计 4–6 回合规划；新增阻断问题需要在相应工作流补修并重验。
若模型账号/客户端权限或原生宿主不可用，验收保持待完成，不能用假数据替代。
不为这些外部条件给出确定日历承诺。

### 当前广义优化路线全部完成：预计还需 15–25 个实质回合（包含上述 v1）

估计基于不新增产品范围、模型/宿主/数据库测试条件可用、没有重大的架构返工。
不等于宣称能与未来所有版本的 gbrain/OpenViking 或所有 Agent 永久完全等价。

| 工作流 | 仍需完成的具体范围 |
| --- | --- |
| PostgreSQL 对等与数据生命周期 | 新 memory/context/事实模块的真实 PG 实现和集成验收、迁移/事务/来源边界及回归；旧 PG 组 PASS 不代替新增模块 |
| 通用记忆整理 | 更广泛中英文偏好、语义冲突/合并、确认与使用记录、衰减/画像；证据、撤回、误判和用户控制必须先设计 |
| 访问控制与数据防泄露 | 可验证的跨项目/来源限制与更完整的 ACL/DLP 威胁模型；当前规则拦截不冒称完整防泄露 |
| 更多宿主与兼容 | Cursor 等确有需求的适配、真实原生生命周期、版本兼容边界；所有可能的未来 Agent 不纳入有限完成承诺 |
| 效果、性能与费用 | 大规模代表性数据、缓存/增量策略、实测任务正确率、嵌入/摘要/提取/重排/重试费用；根据数据决定是否需要 ANN |
| 正式发行 | 签名资质、可复现交付/升级、回滚与文档、最终跨平台/回归/安全验收；签名证书是外部条件，不假装已有 |

15–25 是粗粒度工程区间，不是承诺固定次数；外部验收阻塞、新发现的数据完整性
问题或新增需求可能扩大区间。后续回执应分别写清“实际完成”“未完成”“估计变更
原因”，不再仅报节点号，也不以大量测试计数充当业务完成度百分比。
