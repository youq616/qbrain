# N46D — Embedding response integrity / 向量响应完整性

本轮仅加强 Windows Qbrain 现有文本/图片 Embedding 调用和失败处理，
不新增模型服务、不迁移已有数据库、不自动开启模型外发或写权限。
这不是跨模型/跨服务商向量空间的来源认证；服务端返回有限数值并不能证明
使用了期望的模型。历史存储向量和现有模型标签政策没有在本轮重写。

## 批量响应必须完整且一一对应

文本调用要求 `data` 是数组，条目数与本次输入数完全一致。每个 `index`
必须是范围内的非负整数且不能重复；无论响应按什么顺序返回，输出均按
输入索引排列。不会按服务端提供的巨大索引扩容，也不填补缺项。

向量必须是非空数值数组，能表示为有限 float32，且至少一个分量在转换后
非零。同一批的维度必须一致；文本调用配置 `embedding.dimensions > 0`
时要求实际维度匹配。设置为 `0` 时省略维度请求并从完整响应推断维度，
不是绕过一致性检查。非规范响应会明确失败，不静默截断、归一化或修补。

图片调用仍是现有的服务商自定义 image_url 扩展，不表示标准文本模型
支持图片。为兼容原有单图片网关，只允许单条响应缺省 `index`；有该字段
则必须为整数0，不能返回多个向量。图片不发送文本的 dimensions 参数。

整批校验完成前不会向调用方返回任何向量。异常批次会使现有入库任务失败，
而不是写入部分向量并错误标记完成。这里不宣称所有正常批次的数据库写入
在磁盘故障或并发修改时都具备额外的事务原子性。

## 应用限制（不是各服务商的最大能力）

| 约束 | 当前值 |
| --- | --- |
| 文本批次 | 最多2,048个输入；每项非空有效UTF-8 |
| 单向量维度 | 最多32,768 |
| 一次响应总分量数 | 最多1,048,576 |
| 模型名称 | 非空有效UTF-8，最多1,024字节 |
| 请求JSON | 32 MiB，含转义、Base64与全部字段 |
| 文本响应正文 | 8 MiB |
| 图片响应正文 | 2 MiB，在接收过程中执行 |
| JSON嵌套深度 | 最多16 |
| JSON解析事件 | 最多1,114,112 |
| 单个JSON对象字段数 | 最多128；重复键拒绝 |

这些限制分别约束输入、解析和返回向量，不是整个进程RSS上限。
文本请求在构造完整JSON前计算转义后的实际大小；图片请求在生成Base64前
计算编码总大小。因此24 MiB原始图片会因Base64及JSON开销而超过32 MiB
请求上限；原有32 MiB图片原始输入校验不保证该图片可发送。

文本配置维度与批次数的乘积明显超过总分量上限时，也会在发送前拒绝。
超大批次须由调用方拆分；本轮不会自动增加付费调用或重试。文本空列表
仍是无网络操作的成功空结果。显式QBRAIN_EMBED_MOCK保留历史本地测试行为，
不作为真实模型响应或维度验收。

## 错误与兼容性

两种请求均明确发送 `encoding_format: "float"`。此前忽略 dimensions、
返回Base64向量、漏项/重复项或零向量的非标准网关可能因此明确失败。
应修正接口配置或网关，不要将不完整向量写进脑库。

解析错误只返回固定诊断，不包含JSON解析器的原始异常文本、服务端返回
内容或请求内容。图片失败继续以 unavailable 降级，但向量一定为空。
HTTP重定向、总截止时间、凭据许可等规则沿用N46B，不在本轮放宽。

## 验证与回滚

纯C++畸形输入测试使用与生产相同的解析器；Windows loopback测试调用
真实embed_texts/embed_image、WinHTTP与SQLite入库任务。没有真实付费模型、
用户聊天或用户数据库参与。原N42测试适配器同步新接口并纳入主验证流程；
不会用适配器结果冒充生产存储后端或Windows验收。

待本节点完成后，以N46D-HARD-AUDIT.md中的测试提交、Actions运行和包摘要
为验收依据。可回退本节点的代码/测试/构建变更，无数据库降级迁移。
