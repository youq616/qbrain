# 安装中断与外部配置修改：N47P 恢复边界

本说明对应 N47P 安装器源码修复，不是新发布包。
`windows-preview-c26ec5e5` 的原始安装脚本不包含 N47P 修复，不能用旧脚本验证
这里新增的大日志恢复或输入快照保护。程序 EXE 没有变化；本阶段不覆盖旧发行资产。

## 发生中断后先看状态，不删除 pending.json

对原来相同的 HostName 和 ProjectPath 使用修复后的完整源码目录内脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Install-QbrainMemory.ps1 -Action Status -HostName Claude -ProjectPath 'D:\Projects\MyProject'
```

把路径换为实际项目；原来是 Codex 就保留 `-HostName Codex`。状态查询本身不回滚、
不修复、不证明真实模型已消费上下文。`recovery_required=true` 表示存在待处理日志。
不要将 `installed` 或 `configuration_matches` 单独当作事务已经完成的证明。

关闭正在编辑该项目 Hook/MCP 配置的进程、确认没有其他安装操作，再原样重试原操作。
安装或升级应重试相同宿主/项目/脑库/二进制及**明确选择的开关**；安装器会先检查并
回滚可恢复的待完成事务，再执行这次操作。重装没有重传采集、事实整理或事实召回
开关会关闭对应安装权限，不会自动继承以前的同意。

卸载只在确实要移除该项目接入时使用 `-Action Uninstall`；它不是单独的“只恢复”
命令。它会先处理待恢复事务，再继续卸载原来的有效安装。脑库与备份仍保留。

## 哪些故障现在会被安全拦下

单个配置图像仍以 2 MiB UTF-8 为上限。恢复日志包含多个文件的 before/after 图像，
单独使用 32 MiB 序列化 UTF-8 上限；新日志在初始化脑库和写入备份/配置之前检查，
避免安装器写出自己之后无法读取的聚合日志。合法的超过 2 MiB 的聚合日志可以恢复。

恢复先整体验证版本、字段类型、唯一受管路径、图像类型/编码/预算和所有目标及临时
路径，再检查所有当前文件是否仍等于对应 before 或 after。确定性的后置成员错误
不会让前面文件先回滚。遇到后续真实文件占用或 I/O 错误，日志会留下；解除该错误后
可从已有的 before/after 混合状态重新尝试。

生成安装计划时，读取和转换的输入、所有权验证、journal.before 与备份来自同一组
文本图像。若期间其他程序修改了文件，后续写前检查会拒绝旧计划，而不会重新读取
较新内容并将其错误地当成“允许覆盖”的原图。拒绝原因可能为
`Configuration changed during install.`。此时先保留外部修改，重新检查项目内容后
再决定是否重试；不要以替换备份、删除日志或强行写入绕过检查。

## 无法自动恢复的情况

日志损坏、存在不受管/重复路径、图像非法、目录或 junction 冲突，或当前文件既非
before 也非 after 时，恢复会拒绝并保留日志。保留该项目配置与 integrations 目录，
记录错误再定位原因。日志和备份可能含本地配置及路径，不应直接公开上传。

不要删除原脑库来修复安装；不要把别的项目的 journal/installation.json 复制过来。
没有 `--force` 绕过或跨项目恢复功能。脚本不会绕过宿主信任、授予未选择的采集许可
或将本地文件错误自动外发给模型。

## 明确限制

这是跨多个文件的可重试事务，不是文件系统全局原子事务，也不是针对恶意管理员的
安全认证。多份输入不是同一时刻的原子快照，最后一次比较和实际替换间仍可能发生
外部竞争；安装时应关闭其他配置写入者。原生脑库初始化不属于文件事务，后续中断
可能留下已创建脑库，本修复不自动删除它。

版本 1 日志保留解码后的文本、空字符串与文件不存在的区别，不承诺原 BOM/编码
形式逐字节保留；也没有新增硬链接防御、真实客户端登录验收或 PostgreSQL 对等。
修复依据真实 Windows PowerShell5.1/7 文件测试，但不是对每个用户设备的无缺陷保证。
