# N47I：公开 JSON 输入必须无歧义

本阶段加固会话采集、单条事实写入、MCP 请求正文和 Hook 输入事件。
不新增安装开关、MCP 工具、数据库迁移、模型调用或自动维护动作。

## 重复字段不再静默覆盖

以下输入会被拒绝，即使重复字段的两个值完全一样：

```json
{"fact_id":"第一个值","fact_id":"第二个值","expected_revision":1}
```

此前普通 JSON 解析会丢失较早字段，使后续参数验证无法发现歧义。
现在在解析过程中按每个对象检查字段名。`role` 与 `\u0072ole` 是同一解码名称；
同一对象内二者不能并存。不同消息对象各有 `role` 则完全合法。
大小写不同、Unicode 规范化形式不同的字段不自动合并，用户原话不做规范化。

字符串里面的 JSON 文字不是对象字段，不会因原话讨论重复字段而被删除。
JSON 中转义的 `\u0000` 与原始输入中的 NUL 字节不同：转义字符可按原路由的
字段语义检查，原始 NUL 在入口被拒绝，不能被当成输入结束而忽略后面的字节。

## 错误与限制

| 入口 | 重复字段结果 | 原始字节上限 | 解析事件深度上限 |
| --- | --- | --- | --- |
| memory capture 的 JSON payload | memory_duplicate_key | 262144 | 8 |
| 普通 fact_* JSON payload | fact_duplicate_key | 16384 | 8 |
| lifecycle_batch 的 JSON payload | 保留 fact_batch_duplicate_key | 8192 | 8 |
| MCP 请求正文 | JSON-RPC -32700，id=null，固定 parse error | 16777216 | 32 |
| Hook stdin 事件 | 原有非阻断失败响应 `{}`，不采集或注入上下文 | 262144 | 32 |

深度按随项目交付的 JSON 解析器事件深度计量，包含字段和值，不是原话字符串内的
括号数量。超深或超大的文档会拒绝；正常客户端事件通常远低于这些限制。
MCP 中字符串形式的 payload 会再经过对应的内层解析，不能只靠外层合法绕过。
错误不回显冲突字段、原话、认证材料或本机路径。MCP 无法确定无歧义请求 ID 时
返回 null；包括畸形通知也不会进入工具分发。下一条合法请求仍可正常处理。

Hook 在解析事件成功前不打开脑库、不取得运行锁、不更新追踪或召回状态。
关闭 Hook 时保持原有直接空响应行为。拒绝事件不是成功采集，不是证明客户端
已经消费上下文；本阶段测试是合成进程事件，不是新的 Claude/Codex 登录验收。

## 兼容与范围

唯一字段、合法 UTF-8、在对应大小/深度限制内的有效输入维持原有含义。
来源和写权限检查仍在原位置执行：合法外层下未授权写入仍返回 write_denied，
不能靠畸形 payload 获得额外权限。此处没有宣称旧行为能绕过身份认证。

不重写历史已归档文本、数据库、安装器所有的配置文件或旧事实。已存证据仍按
原有完整性规则复核。其他文件解析入口和 NDJSON 传输性能不是本次全面审计范围；
输入字节限制也不等于完整操作的内存、数据库 I/O 或延迟保证。

升级后自行构造请求的脚本应输出一次且仅一次的字段。不要通过换字段顺序或删除
错误断言来恢复重复字段输入。官方正常 JSON 序列化生成的对象一般不会产生重复键。

参考：RFC 8259 第4节建议对象名称唯一；本项目选择拒绝作为明确的应用输入政策。
https://www.rfc-editor.org/rfc/rfc8259#section-4
