# Windows 大小写敏感目录的安装边界（N47V）

本说明对应 N47V 新源码中的 Install-QbrainMemory.ps1。现有 N47R 公开包没有本次
检查；本轮不发布或覆盖安装包，也不要求用户现在升级。

## 为什么拒绝这类路径

原安装身份由宿主名和转小写的完整项目路径生成。在大小写敏感的 NTFS 父目录中，
Project 和 project 可以是不同目录，却得到相同身份，造成读取另一项目安装记录的
风险。N47V 保留普通目录的历史身份，明确拒绝大小写敏感或无法验证的目录，而不是
擅自换 ID、合并项目、搬动资料或修改系统属性。这不等于完整支持大小写敏感项目。

检查覆盖项目自身和现存祖先、受管配置及临时文件、备份/安装数据和程序路径的相关
现存目录。Install、Uninstall 和 Status 都使用检查；Status 报错不能被解释为未安装。
在已知不支持的程序路径上，拒绝发生在创建安装记录目录之前。

## 遇到拒绝时的处理

错误可能为 Case-sensitive directories are not supported for integration configuration，
或 Cannot verify directory case sensitivity / attributes。后者表示无法证实路径安全，
不能将其视为大小写不敏感。链接或检查途中替换成普通文件的目录也会拒绝。

保留原项目配置、安装记录、备份和 pending.json；不要手工复制另一个项目的记录、
删除恢复日志、强制重装、关闭权限检查或直接关闭目录大小写敏感属性。已有两个仅
大小写不同的项目时，需要先分别确认其实际目录、关联脑库和宿主配置，再制定明确
迁移方案。本阶段没有实现这样的自动迁移，也不会自动合并或删除脑库。

只需查看目录属性时，可在自己的 Windows 窗口使用以下只读命令，替换为实际目录：

```powershell
fsutil.exe file queryCaseSensitiveInfo 'D:\Projects\MyProject'
```

这个命令只查询指定目录，不代表全部祖先已验证；本地查询失败也不是安全证明。
产品检查直接调用原生 API，不解析本地化 fsutil 输出。不要将这条查询改成 set 命令。

普通、可验证的大小写不敏感路径继续使用原安装器命令、历史安装 ID 和明确授权的
采集/事实开关。无法使用 Add-Type、原生元数据查询不受支持或读取权限不足的环境
会失败关闭，不要求绕过安全策略。程序运行仍不需要 Docker、WSL 或 Python 服务。

## 已验证范围与剩余限制

两版原生 PowerShell 的真实 NTFS 用例证明旧身份冲突，并验证新检查拒绝后临时项目
和安装文件未被改动。另行测试了检查期间目录消失，以及被文件或 junction 替换的
情形。普通安装、重装、卸载、快照与中断恢复回归保留。

这些是受控时序测试，不保证检查之后不存在竞态，不是恶意本机管理员防护，也不
覆盖所有文件系统、网络盘或受限语言环境。Add-Type 类型可复用，但目录属性不缓存。
旧恢复事务、默认权限和运行时没有在本阶段重写。

一次旧 Codex Hook 在 CI 中超过原 10 秒限制；相同版本重跑通过，根因仍未确定，见
[Issue40](https://github.com/youq616/qbrain/issues/40)。路径检查通过不代表该可靠性问题
已修复，也不等于真实客户端、模型消费、PG 或稳定版最终验收通过。
