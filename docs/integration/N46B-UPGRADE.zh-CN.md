# N46B 升级注意事项：Windows 模型请求边界

本说明只适用于 Windows 原生 Qbrain 的 N46B 代码。具体通过验收的源码、日志与二进制摘要见 `../nodes/N46B-HARD-AUDIT.md`；不能凭旧的内部版本号判断安装包是否包含修复。

## 接口地址与认证

模型服务的基础地址必须使用 HTTP 或 HTTPS，并直接指向最终 API，不再自动跟随 301、302、307 等重定向，包括同域跳转。配置示例是 `https://provider.example/v1`，不是一个会跳转到真实 API 的网页入口。基础地址不接受用户名、密码、查询参数或片段；密钥使用现有独立 API key 配置，不拼进 URL。

路径连接统一处理尾部斜线：基础地址 `/v1/` 与接口 `/chat/completions` 连接为 `/v1/chat/completions`。Bearer key 不允许控制字符、空格或非 ASCII 字节。WinHTTP 自动认证与 Cookie 关闭，但显式配置的 Bearer header 仍然发送。系统 TLS 证书验证没有关闭；远端接口应使用 HTTPS。保留 HTTP 是为了兼容明确配置的本地模型服务，不表示 HTTP 已加密。

## 大小与时间限制

响应正文默认最多 8 MiB。C++ 调用方可显式传入 1 byte 至 64 MiB 的上限；这不是新增的 CLI 配置项。无论有无 Content-Length，读取时都会检查实际字节；响应头由 WinHTTP 限制为 64 KiB。

**请求 JSON 最多 32 MiB，这不是原始图片的 32 MiB。** 图片 Base64 编码会增大正文，因此接近 24 MiB 的原始图片可能因 JSON、模型字段和编码开销而超限。旧图像包装层的原始输入校验不代表该图一定符合新的传输上限；超限会明确失败而不是绕过限制。现有落盘文件和记忆库格式没有变化。

传输默认 60,000 ms，chat 包装层保留原来的 120,000 ms 默认值，记忆提取显式传入 60,000 ms。发送、响应头、逐块读取使用同一个单调时钟截止时间；持续滴流不能重置整次网络等待时限。该约束不是对操作系统调度、句柄销毁或整个维护批次的硬实时承诺，批次仍按原有策略在调用间检查预算。

## 错误与隐私

断流、超时、超限或长度不符时，传输层不返回半截正文，也不把已经收到的 200 状态当作成功。非 2xx 只返回状态错误，不回显服务端错误正文；部分网关的详细错误信息因此不再直接显示。这不是完整的全应用日志、DLP、进程内存擦除或备份擦除审计。

本次不会自动开启模型外发、记忆采集或 MCP 写权限，不迁移数据库。升级前仍应备份已有脑库；不要使用历史 `dist/` 文件替代带有本轮来源清单的已验证包。正式签名、真实登录 Agent 生命周期和付费模型质量/费用验收仍是独立事项。
